# YOLO 系列总表：优点 / 缺点 / 具体改进

> Living doc：后续问答会直接改本文件。  
> 依据 `docs/yolo-survey/` 各版中文译本整理。  
> 跨论文的绝对 AP/FPS **不可严格同台对比**（硬件、是否含 NMS、是否预训练不同）；表内数字优先采用「同文相对提升」或该版官方/论文自报量级。

---

## 总表

| 版本 | 具体优点 | 具体缺点 | 相对前代的具体改进 |
|------|----------|----------|-------------------|
| **v1** | 整图一次前向直接出框（端到端）；在当时旗舰 GPU（NVIDIA Titan X）上约 45 帧/秒，轻量 Fast YOLO 约 155 帧/秒；把背景误当成物体的情况约为当时 Fast R-CNN 的一半；从自然照片换到油画/素描等外观差异大的图时掉点更少 | 同一网格格子难同时检多类；框位置偏粗；小目标漏检多 | （开创）检测改成网格回归，去掉「先提候选框再分类」的两阶段流水线 |
| **v2** | 相对 v1 召回与定位明显提升；k-means 锚框先验更贴数据；多尺度训练使一套权重可多分辨率推理 | 特征仍偏浅；极小目标与极密集场景仍弱 | **Anchor + 维度聚类**；中心用 σ 约束进 cell；passthrough 融细粒度特征；多尺度训练 |
| **v3** | Darknet-53 精度接近当时 ResNet 路线但更快；**三尺度**头显著补小目标；logistic 多标签适配重叠类别 | 相对两阶段仍偏「框不够贴」；结构与超参开始变多 | 更深骨干；FPN 式 **P3/P4/P5**；多标签分类替代单标签 softmax |
| **v4** | 系统整理 BoF/BoS；CSP + PAN + Mosaic + CIoU 把实时检测重新拉到当时 SOTA；训练技巧可迁移 | 模块组合多，消融与复现成本高；Darknet 工程门槛高于后来的 PyTorch 系 | CSP 骨干、PAN 自下而上路径、Mosaic、CIoU、CmBN 等**可复用训练包** |
| **v5** | n/s/m/l/x 一条缩放链；C3 + SPPF；train/val/export（ONNX/TRT 等）一体化，落地快 | 经典头仍是 **anchor-based 耦合头**，换数据集常要重估锚框；后期精度上限逐渐被 v7/v8 超过 | 把 v3/v4 思想产品化为 **PyTorch 缩放族 + 强增广默认配方 + 导出链** |
| **v6** | Rep 训练多分支、推理融为 3×3；T4 上 N 档约 **35.9% AP / ~1234 FPS**，量化 S 约 **43.3% AP / ~869 FPS**；TAL + VFL 对齐分类与定位 | Rep/QAT 需配套训练流程；与 Ultralytics 权重/API 不通用；N/S 与 M/L 块设计不统一 | **Rep-PAN + 高效解耦头 + anchor-free**；面向 INT8 的量化友好训练 |
| **v7** | E-ELAN 加深不易毁梯度；相对 YOLOR-CSP 约 **−43% 参数、−15% 计算、+0.4 AP**；E6E 实时档约 **56.8% AP**；COCO **从零训练** | Lead/auxiliary 粗细标签理解成本高；concat 复合缩放规则与普通 width/depth 缩放不通用 | **E-ELAN**；面向 concat 的复合缩放；**RepConvN**（残差/concat 层去掉 identity）；coarse-to-fine lead 分配 |
| **v8** | **C2f** 把中间特征一并 concat；**无锚解耦头 + DFL（reg_max=16）**；原生 detect/seg/pose/obb/cls；自定义数据少调锚 | 默认仍依赖 **NMS**；同精度参数量不如后续 v10 极限；未系统引入大核/注意力 | 相对 v5：无锚 + 解耦 + DFL + C2f；多任务统一进同一 API |
| **v9** | PGI 辅助可逆分支只在训练存在、推理无额外成本；GELAN 常规卷积参数利用率高；YOLOv9-E 约 **55.6% AP**，相对 v8-X 更少参/算且约 **+1.7 AP** | 训练计算图更重（辅助分支）；多任务/导出一体性弱于 v8/11 全家桶 | 对准深层信息瓶颈：**PGI 可编程梯度** + **GELAN**（可换计算块） |
| **v10** | 推理走一对一头 → **NMS-free**；S 档相近 AP 下比 RT-DETR-R18 约快 **1.8×**、参/算约 **2.8×** 更小；相对 v9-C，B 档延迟约 **−46%** | 一对一头质量依赖 consistent matching；多任务广度弱于 Ultralytics 主线；部署需确认已去掉 NMS | **双分配一致匹配**；轻量分类头；空间–通道解耦下采样；CIB；PSA |
| **YOLO11** | 相对 v8m 约 **−22% 参数**且 mAP 更高；C3k2 + C2PSA；n…x 检测/分割/姿态/OBB/分类权重齐全；文档与导出支持完整 | 默认仍走 NMS（不是 v10 的端到端命题）；论文表峰值不一定压过 v12/v13 | 相对 v8：**C3k2 换 C2f**、加入 **C2PSA**、分类支路更轻 |
| **v12** | Area Attention 分区降注意力成本；N 档约 **40.6% mAP @ ~1.64 ms（T4）**，相对 v10-N / YOLO11-N 约 **+2.1 / +1.2** | 注意力训练更吃显存；CPU/部分导出路径易变慢；大模型需 R-ELAN 残差缩放才好训 | 用 **Area Attention + R-ELAN + FlashAttention** 把注意力拉进实时区 |
| **v13** | HyperACE 学习连续超边参与度（非手工阈值）；FullPAD 把增强特征分回骨干/颈/头；N 档约 **41.6% AP**，相对 YOLO11-N / v12-N 约 **+3.0 / +1.5** | 超图 + 全管线分发使结构更重；同档延迟高于 YOLO11（N 约 1.97 vs 1.5 ms 量级）；中大模型边际收益变小 | 从 pairwise 注意力升级到 **多对多高阶相关**；DS 块降参降算 |
| **v14** | 同一框架覆盖鱼眼 / 游戏→真实 / 无人机 / 360°；AdaIN + 域对抗；6 类 ViewEmbedding；DeformableAAttn + CircularConv | 公开完整 COCO/延迟主表仍少；变体多，数据与场景管线更重；优化目标不同于通用 COCO 刷榜 | 命题转为 **非理想成像跨域**：场景路由增强 + 域对齐 + 可变形/球形模块 |

## 相邻代改进因果（短表）

| 从 → 到 | 对准的具体痛点 | 落地改动（可指认模块） |
|---------|----------------|------------------------|
| v1 → v2 | 同格冲突、框回归不稳 | Anchor、聚类先验、σ 中心、passthrough |
| v2 → v3 | 小目标、语义不够深 | Darknet-53、三尺度头 |
| v3 → v4 | 训练散、融合弱 | CSP、PAN、Mosaic、CIoU |
| v4 → v5 | 难用、难部署 | PyTorch、n–x 缩放、SPPF、导出链 |
| v5 → v6 | GPU 产线吞吐 / 量化 | RepBlock、解耦头、TAL、QAT/PTQ |
| v5/v6 → v7 | 加深易毁梯度、分配乱 | E-ELAN、RepConvN、lead 粗细分配 |
| v5 → v8 | 锚框调参、头任务耦合 | C2f、无锚解耦、DFL、多任务 |
| v8 → v9 | 深层信息丢、梯度不可靠 | PGI、GELAN |
| v8/v9 → v10 | NMS 延迟与方差、组件冗余 | 双头一致分配、CIB/PSA、解耦下采样 |
| v8 → YOLO11 | 参数偏多、小目标/遮挡 | C3k2、C2PSA、更轻分类头 |
| YOLO11 → v12 | CNN 全局建模不足 | Area Attention、R-ELAN |
| v12 → v13 | 只有成对相关 | HyperACE、FullPAD |
| * → v14 | 针孔真实图假设失败 | 域自适应、多视角、可变形/全景模块 |

## 选型速查

| 需求 | 更合适 | 理由 |
|------|--------|------|
| 学思想递进 | v1 → v3 → v4 | 概念链路最清楚 |
| 通用检测 / 分割 / 姿态 | **YOLO11**（或 v8） | 生态完整、默认稳定 |
| GPU 吞吐 / INT8 产线 | **YOLOv6** | Rep + 量化路径 |
| 从零训练 / 梯度理论 | **v7 / v9** | BoF 与 PGI |
| 去掉 NMS、压端到端延迟 | **YOLOv10** | 一致双分配 |
| 注意力实时化（实验） | v12 | 注意显存与 CPU |
| 复杂场景高阶关系（实验） | v13 | 注意结构与延迟成本 |
| 鱼眼 / 游戏 / 无人机 / 全景 | **YOLOv14** | 跨域非理想成像 |

## 术语速查（读 v1 行时常用）

| 术语 | 含义 |
|------|------|
| **Titan X** | 2015 年前后 NVIDIA 桌面旗舰 GPU；YOLOv1 论文用它报速度，便于当时横向对比。不是算法名。 |
| **FPS** | Frames Per Second，每秒处理多少张图。越高越快；谈 FPS 必须带硬件（如 Titan X / T4）才有意义。 |
| **Fast R-CNN** | 两阶段检测器：先有一批候选区域（region proposals），再对每个候选做分类/精修。流水线长，通常更慢。YOLO 是单次整图回归。 |
| **背景假阳性少** | 假阳性 = 把「没有物体的背景」报成「有某个物体」。少 = 更少乱框、更少「空背景被当成车/人」。YOLOv1 因看整图上下文，这类错比 Fast R-CNN 少约一半。 |
| **跨域更稳** | 「域」= 数据外观分布（如手机实拍 vs 油画）。跨域 = 训练域和测试域不一样。更稳 = 换风格后性能跌得少，不那么容易「只会认训练集那种照片」。YOLOv1 举例：自然图训练，艺术品测试。 |
